# Model Training Pipeline for Bank Marketing Prediction

## Objective
This pipeline trains and evaluates various classification models to predict term deposit subscriptions by customers. It involves comparing multiple models, performing hyperparameter tuning on a selected model, and tracking experiments using MLflow. The best performing tuned model is saved for inference.

## Input
-   `bank-features-selected.csv`: A CSV file containing the selected features and the target variable ('y'). This file is expected to be generated by the `feature_engineering.ipynb` notebook in the `../feature_pipeline/` directory.
-   `selected_feature_names.json` (optional, for reference): A JSON file from `../feature_pipeline/` listing the names of the selected features. The notebook primarily relies on the columns from the CSV.

## Processing Steps
The `model_training.ipynb` notebook executes the following key steps:

1.  **Load Data**:
    -   Loads the `bank-features-selected.csv` dataset.
    -   Separates features (X) and the target variable (y).
    -   Performs necessary checks and cleaning on the target variable (e.g., handling NaNs, ensuring integer type).

2.  **Train-Test Split**:
    -   Splits the data into training (80%) and testing (20%) sets, using stratification on the target variable to maintain class proportions.

3.  **LazyPredict Comparison (Optional)**:
    -   If `lazypredict` is installed, it runs `LazyClassifier` to get a baseline performance overview of multiple classification algorithms without extensive tuning.
    -   Results (Accuracy, F1-score, ROC AUC, etc.) are displayed to help inform model selection.

4.  **MLflow Experiment Setup**:
    -   Sets up an MLflow experiment (e.g., "Bank Marketing Predictions"). If the experiment doesn't exist, it's created.

5.  **Initial Model Training (Baseline)**:
    -   A selected model (e.g., RandomForestClassifier, potentially guided by LazyPredict) is trained with default or basic parameters.
    -   This model is evaluated, and its performance metrics are displayed.
    -   The initially trained model is saved (e.g., `randomforestclassifier_model.joblib`).
    -   This initial model can also be optionally logged to MLflow for comparison.

6.  **Hyperparameter Tuning**:
    -   A model is selected for tuning (e.g., RandomForestClassifier, GradientBoostingClassifier, LogisticRegression), potentially guided by LazyPredict's top performers.
    -   A parameter grid is defined for the selected model.
    -   `GridSearchCV` (with 3-fold cross-validation and `f1_weighted` or `roc_auc` scoring) is used to find the optimal hyperparameters on the training data.

7.  **MLflow Tracking for Tuned Model**:
    -   A new MLflow run is started for the tuned model.
    -   **Logged Parameters**: Model type, best hyperparameters from GridSearchCV, and the list of feature names.
    -   **Logged Metrics**: Accuracy, F1-scores (weighted, macro, and for the positive 'yes' class), Precision (weighted and macro), Recall (weighted and macro), and ROC AUC are calculated on the test set and logged.
    -   **Logged Artifacts**:
        -   The classification report (as a text file).
        -   A plot of the confusion matrix (as a PNG image).
        -   A plot of feature importances (if applicable for the model, as a PNG image).
        -   The trained (tuned) scikit-learn model itself using `mlflow.sklearn.log_model()`.

8.  **Model Export**:
    -   The best model obtained from hyperparameter tuning (via `GridSearchCV.best_estimator_`) is saved locally as `best_tuned_model.joblib` in the `training_pipeline` directory. This is the primary model artifact intended for the inference pipeline.

## Output
-   **`best_tuned_model.joblib`**: The best performing, tuned classification model saved using `joblib`. This is the primary output for the inference pipeline.
-   **(Optional) `{model_name}_model.joblib`**: The initially trained model (before tuning) is also saved.
-   **MLflow Experiment**:
    -   **Experiment Name**: "Bank Marketing Predictions" (or as configured in the notebook).
    -   **Runs**: Contains runs for the initial model (optional) and the tuned model.
    -   **Logged for each run**: Parameters, metrics (Accuracy, F1, Precision, Recall, ROC AUC), and artifacts (model file, classification report, confusion matrix plot, feature importance plot).

## How to Run
1.  Ensure the feature engineering pipeline has been run and `bank-features-selected.csv` is available in `../feature_pipeline/`.
2.  Have a Python environment with necessary libraries installed (see `bank_marketing_project/requirements.txt` - this file should be created and populated). Key libraries: pandas, scikit-learn, matplotlib, seaborn, joblib, mlflow, and optionally lazypredict.
3.  Ensure an MLflow tracking server is running or that MLflow is configured to log locally (default).
4.  Open and run the `model_training.ipynb` Jupyter notebook from within the `bank_marketing_project/training_pipeline/` directory.
5.  The notebook will load data, train models, perform tuning, log results to MLflow, and save the `best_tuned_model.joblib`. You can then view the experiment details in the MLflow UI.
